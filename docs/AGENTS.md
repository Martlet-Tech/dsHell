# 文档规范

本文件是全项目文档的唯一权威规范。子目录的 `AGENTS.md` 只写局部增量，与本文件冲突时以本文件为准。

## 文档地图

| 位置 | 写什么 | 面向 | 可删改 |
| --- | --- | --- | --- |
| `README.md` | 是什么、怎么跑 | 使用者 | 随功能更新 |
| `docs/design.md` | 为什么这么做、实测数据、踩过的坑 | 维护者 | 只增不删 |
| `docs/roadmap.md` | 还没做的事，按优先级排 | 维护者 | 做完即删条目 |
| `docs/plan/` | 在办升级项的完整推导 | 维护者 | 可改，收口后移入 `closed/` |
| `docs/closed/` | 已收口的升级项 | 维护者 | 冻结只读 |

## 核心规则

- **一个升级项 = 一份文档**。不按轮次横向拆分（方案一份、代码一份是反面例子）。
- **一主题一文件**。同一主题的内容放同一份，不散落。
- `roadmap.md` 是**唯一待办入口**：立项时从它取，收口时把对应条目删掉。

## plan 文档三段式

| 段 | 内容 |
| --- | --- |
| ① 方案 | 改什么、为什么、改完是什么样。不含实现代码 |
| ② 关键代码 | 接口契约、数据结构、关键片段 |
| ③ 结案总结 | 实测结果、预期与实际的差异、遗留项 |

写到 ③ 才算收口，之后移入 `closed/`。

## 写作约定

- 文件名 kebab-case，带立项序号前缀：`03-single-instance.md`。
- 用中文；实测数据一律用表格，并标注测量时间与环境。
- 表格优先于长段落；一句能说完的不写三句。

## 边界

- `docs/` 在 git 仓库内，可正常做 git 操作。
- 外层 `D:\Projects\dsh-shell\` **不是** git 仓库，禁止在那里做 git 操作；其 `AGENTS.md` 不可修改。
